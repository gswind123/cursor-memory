# stack-memory · 只读流程（use-stack-memory）

## 契约与引用约定

- **公共契约**：分层语义、权力顺序、共用禁止项、**Root（候选路径列表与解析算法）**以规则 **`stack-memory`** 为准；**何时读取**由本技能定义（规则不再重复触发条件）。
- **按名字引用**：提及其它规则或技能时仅用名称（如 **`stack-memory`**、**`archive-stack-memory`**），不使用仓库内文件路径。

## 启用条件

当用户**明确希望本次回答参考 stack-memory 落盘内容**且意图为**只读参考**（非归档）时启用本技能。典型情形：

- 用户在 Cursor 中**附加了本技能**，并要求据此检索记忆；或
- 用户消息中同时包含「memory / 记忆 / 偏好 / 风格 / 历史项目 / 以往习惯」一类用语，且明确指向 **stack-memory**、**分层记忆**，或 L0–L3 / `INDEX` 式分层检索。

**弱触发（不要启用）**：仅「帮我写 API」「重构这段代码」等，未附加本技能且未要求参考 stack-memory。

## 不适用

- 用户意图为**写入 / 归档**：改用技能 **`archive-stack-memory`**；本技能不修改任何落盘文件。

## 只读边界（硬约束）

- **禁止**创建、修改、删除 stack-memory **root** 下任意文件（含 `INDEX.md`、各层 README）。
- **禁止**执行技能 **`archive-stack-memory`** 或 **`archive-flow-memory`** 的写入流程。
- 仅读取与当前任务相关的必要片段，完成当前回答。

## Root 解析（必须先执行）

- **候选列表、解析顺序、合法性检查**以规则 **`stack-memory`** 中「Root（可变锚点）」为准（单一事实来源）。
- **第一步**：按规则中的列表自上而下探测工作区内路径；第一个同时包含根下文件 **`INDEX.md`** 与目录 **`L1_project_knowledge/`** 的路径即为本次任务的 **root**。
- **禁止**在列表外猜测路径；**禁止**自动创建目录或「假定」root。

### Root 解析失败（硬中断）

若无任何候选通过合法性检查：

1. **停止**：不读取任何记忆文件；**不**输出常规「Memory 约束提要 / 回答正文」替代完整任务。
2. 仅向用户输出**错误说明**，须包含：
   - **诊断**：未解析到有效 stack-memory root（已按规则尝试全部候选路径）。
   - **修复**（任选其一）：将完整原型目录放到某一候选路径下并保证含 `INDEX.md` 与 `L1_project_knowledge/`；或编辑全局规则 **`stack-memory`**，在「候选 root 路径列表」中加入你的相对路径并置顶/调序。
   - **默认可复制列表**（与规则默认一致）：

```
./stack-memory/
./.workspace/stack-memory/
stack-memory/
.workspace/stack-memory/
```

## 读取顺序（少而精）

相对 stack-memory **root**：

1. `INDEX.md` — 先索引后条目，避免递归扫全库。
2. 按权力顺序 **L0 > L1 > L2 > L3** 打开与当前任务最相关的少量文件；优先 L0/L1 作为硬约束来源（权力顺序以规则 **`stack-memory`** 为准）。
3. L2/L3 不得推翻 L0/L1；冲突时以 L0/L1 为准并在输出中简要说明。

## 输出契约

1. **Memory 约束提要**：列出与任务直接相关的要点（建议 3–7 条）；注明类别（如硬规则 / 目标 / 决策 / 示例模式 / 踩坑）。
2. **回答正文**：按上述约束实现；逐条对齐；若某条在 memory 中**未找到**，标注「memory 未提供」并以行业默认最佳实践补全且声明为推断。
3. **仅当 root 已成功解析后**：若某文件缺失或某条目为空，说明情况并按第 2 条标注「memory 未提供」与推断。若 **root 未能解析**，只能输出上文「Root 解析失败」错误说明，**不得**假装已读记忆或仅用默认实践完成主任务。

## 用户可复制的强触发话术（示例）

以下话术有助于**显式触发**只读检索（可与附加本技能配合使用）：

**方法 1 · 显式唤醒**

> 在回答前请先读 **stack-memory**，并把其中与本次任务相关的偏好与约束当作主约束。

**方法 2 · 点名内容类型**

> 基于我以往技术栈与编码偏好（memory），请先读 **stack-memory** 再完成：……

**方法 3 · 先加载再执行**

> 先总结你从 **stack-memory** 得到的与本次相关的约束提要，再基于该提要完成任务。
